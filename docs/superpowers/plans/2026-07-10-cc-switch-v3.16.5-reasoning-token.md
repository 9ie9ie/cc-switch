# CC Switch v3.16.5 Reasoning Token Display Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在官方 CC Switch `v3.16.5` 上恢复当前使用的 Codex reasoning token 显示与红色标记功能，并构建可在 E 盘独立运行的 Windows 版本。

**Architecture:** 从 tag `v3.16.5` 创建干净分支，以提交 `2a4c131a` 作为唯一功能补丁来源。后端统一解析、持久化并返回 reasoning token，前端只负责显示和 `518n - 2` 告警；GitHub Actions 生成独立的 Windows 可执行文件。

**Tech Stack:** Rust, Tauri, SQLite/rusqlite, React, TypeScript, Vitest, pnpm, GitHub Actions

## Global Constraints

- 基线必须是官方 tag `v3.16.5`，tag commit 为 `8d1b3306`。
- reasoning token 功能来源必须是提交 `2a4c131a`。
- 数据库版本必须保持 `SCHEMA_VERSION = 12`，不得降级、重建或删除现有数据库。
- 红色标记值必须严格为 `516`、`1034`、`1552`、`2070`，即 `518n - 2` 且 `1 <= n <= 4`。
- reasoning token 为 `0` 或字段缺失时不得显示推理行。
- 不得加入未提交的 `codex_reasoning_events`、`codex_reasoning_sync`、`codex_reasoning.rs` 或 `analyze_codex_reasoning.py`。
- 不得修改当前脏 worktree `cc-switch-reasoning-latest` 中已有的未提交文件。
- 新程序必须部署到 `E:\INSTALL\CC Switch Reasoning 3.16.5`，保留现有 `E:\INSTALL\CC Switch Reasoning` 和 `E:\INSTALL\CC Switch`。
